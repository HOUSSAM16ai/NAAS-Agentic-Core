# Dual-Track Product System — Engineering and Foreign-Currency Production

## Constitutional purpose

NAAS-Agentic-Core is governed as one product with **two explicit tracks**. The tracks are separate in responsibilities and evidence, but inseparable at release:

| Track | Primary question | Required evidence |
|---|---|---|
| **Engineering/Product Track** | هل يعمل المنتج فعلاً؟ هل هو آمن، قابل للصيانة، قابل للمراقبة، وقابل للتوسع؟ | معايير المستودعات، الأبحاث، المقررات، العقود، الاختبارات، الأداء، الأمن، provenance، والحقيقة التشغيلية. |
| **Production/Commercial Track** | هل يحل مشكلة مدفوعة ويمكن تسليمه وتحصيله بالعملة الصعبة مع أثر جزائري؟ | عميل مستهدف، مشكلة مدفوعة، عرض، تجربة، دليل قيمة، عقد/دفعة عند التفعيل، هامش، مالك تسليم، ومسار تحصيل قانوني. |

> **قاعدة الالتقاء:** لا يكفي أن يكون الكود ممتازاً إذا لم ينتج قيمة قابلة للبيع، ولا يكفي أن يوجد طلب تجاري إذا كان المنتج غير آمن أو غير قابل للإنتاج. الإصدار أو تفعيل العرض يحتاج دليلاً من المسارين أو استثناءً مؤسسياً موثقاً.

## Track A — Engineering/Product

مسار الهندسة يطبق عمود المستودعات المرجعي، مصفوفة المصادر الكاملة، كتالوج المقررات، الأدلة الرسمية، وبوابات الجودة. كل إضافة تحدد نوعها: خوارزمية، خدمة، بيانات، نموذج، وكيل، أداة، واجهة، بنية، نشر، أو إصلاح أمني. ثم تُحمّل المجالات الأكاديمية والمعايير المناسبة وتثبتها في حزمة التغيير.

النتيجة المطلوبة ليست «كوداً كثيراً»، بل قدرة قابلة للاستدعاء بحدود واضحة، عقد، اختبار، رصد، مالك، ومسار فشل. كل ادعاء عن الدقة أو الأمان أو الجاهزية أو التوسع يحتاج دليلاً محلياً؛ القراءة أو الاستلهام لا يُساوي تطبيقاً.

## Track B — Production/Commercial

مسار الإنتاج والتجارة يحول القدرة الهندسية إلى عرض يخدم عميلاً خارج الجزائر أو سوقاً تصديرية قابلة للتحقق. يبدأ من مشكلة مدفوعة، وليس من تقنية جذابة. يحدد العرض نطاق التسليم، دليل الندرة، نتيجة العميل، طريقة التجربة، المالك، التكلفة، شروط الدعم، ومتطلبات الامتثال قبل أي وعد.

العملة الصعبة ليست شعاراً. لا تُسجل حالة `PAID_PROOF` أو `REPEATABLE` إلا بدليل قابل للمراجعة مثل عقد، أمر شراء، دفعة، اشتراك، أو تجديد موثق؛ وتحتاج الشؤون القانونية والمحاسبية والدفع إلى مراجعة مختصة قبل التنفيذ الفعلي.

## Shared alignment contract

يجب أن يرتبط كل عنصر في المسارين عبر `alignment_id` واحد. يربط هذا المعرّف القدرة، العميل، المشكلة، العرض، المستودعات، المقررات، الأدلة، اختبار القبول، المالك، حالة الحقيقة، ومسار الإيراد. لا يسمح النظام بوجود «ميزة يتيمة» أو «عرض بلا قدرة».

| حالة | الهندسة | الإنتاج/التجارة | القرار |
|---|---|---|---|
| `RESEARCH` | فرضية أو تجربة معزولة | لا وعد تجاري | لا إصدار، ولا ادعاء إنتاج. |
| `BUILDING` | تنفيذ واختبارات أولية | اكتشاف عميل/مشكلة | تجربة داخلية أو pilot محدود فقط. |
| `PILOT_READY` | أدلة تقنية وحدود معروفة | نطاق تجربة ومالك وقياس | تجربة مضبوطة بموافقة واضحة. |
| `PAID_PROOF` | قدرة إنتاجية ضمن نطاق | عقد أو دفعة موثقة | يمكن تفعيل العرض ضمن النطاق. |
| `REPEATABLE` | تسليم وتشغيل ومراقبة قابلة للتكرار | تجديد/تكرار وهامش معروف | يسمح بالتوسع بعد مراجعة المخاطر. |

## Non-bypass rules

1. لا يمكن للوكيل ترقية حالة تجارية اعتماداً على نجاح اختبار تقني فقط.
2. لا يمكن للوكيل إصدار قدرة إنتاجية اعتماداً على عقد فقط دون برهان تقني وأمني.
3. لا يمكن للوكيل إضافة عرض جديد خارج `OFFER_CATALOG.json` دون بطاقة وقدرة وقرار.
4. لا يمكن للوكيل إعلان أثر على التعليم أو البطالة أو سوق الشغل دون مقياس وتعريف ودليل.
5. لا يمكن للوكيل تحويل عدد الوكلاء أو الملفات أو النجوم أو الزيارات إلى إيراد.
6. لا يمكن للوكيل حذف أصل أو مصدر أو دليل تاريخي لمعالجة عدم الاتساق؛ يضيف سجلاً أو قراراً يصحح الحالة.

## Algerian value and export logic

الهدف الوطني هو بناء قيمة تقنية قابلة للتصدير: **تكلفة معرفة وهندسة محلية، وقيمة مبيعة لعميل خارجي، مع تنمية مهارات وفرص عمل داخل الجزائر**. قياس ذلك يحتاج فصل الإيراد المحصل عن pipeline، وفصل الأثر التدريبي عن التوظيف الفعلي، وتوثيق القيود بدل تضخيمها.

المؤشرات التشغيلية المقترحة هي الإيراد المحصل بالعملة الصعبة، عدد العقود والتجديدات، هامش التسليم، زمن الوصول إلى أول قيمة، معدل فشل الإنتاج، وقت الاستعادة، نسبة القدرات التي لها دليل عميل، وعدد المتعلمين الذين انتقلوا إلى مهارة أو عمل موثق. هذه مؤشرات قياس وليست ضمانات أو استشارات ضريبية أو قانونية.
