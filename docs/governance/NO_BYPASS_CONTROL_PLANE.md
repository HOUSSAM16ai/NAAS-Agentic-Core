# نموذج التحكم ضد تجاوز التوثيق

## الغرض

هذه الوثيقة لا تدّعي أن نصًا داخل مستودع يستطيع منع مالك حساب يملك صلاحيات الإدارة من تغيير المنصة نفسها. هدفها هو تحويل التوثيق من اتفاق اجتماعي إلى **سطح قبول متعدد الطبقات**: أي تغيير يمر عبر البوابات، ولا يُقبل الدمج إذا غابت إحدى الطبقات المطلوبة.

## طبقات الضمان

| الطبقة | الحماية | حالة الإنفاذ |
|---|---|---|
| المصدر | `DOCUMENTATION_MANIFEST.json` يعلن الوثائق الحية و`**/*.md` يوسّع النطاق إلى كل Markdown غير مؤرشف | مفروضة بواسطة `check_documentation_contract.py` |
| المحتوى | الروابط المحلية، المسارات، الأوامر القديمة، والحقول الناقصة تفشل صراحة | مفروضة في `guardrails` و`doc-integrity` |
| الوكيل | `AGENTS.md` و`AGENT_CODE_CHANGE_PROTOCOL.md` يمنعان تجاوز الفشل أو تعديل البوابة ذاتيًا | مفروضة نصيًا وآليًا ببوابات القبول |
| البرهان | اختبارات سلبية تثبت أن manifest أو رابطًا مكسورًا يسبب رفضًا فعليًا | `tests/fitness/test_documentation_contract_gate.py` |
| CI | `required-ci` يعتمد مباشرة على `guardrails`، و`doc-integrity` مطلوب كفحص مستقل | مفروضة في `.github/workflows/ci.yml` |
| GitHub | حماية `main`: مراجعة CODEOWNERS، فحصان مطلوبان، منع force-push والحذف، سجل خطي، وحل المحادثات | مفروضة في إعدادات الفرع ومتحقق منها عبر API |
| إدارة التغيير | سياسة الحماية المرغوبة محفوظة في [`branch-protection-policy.json`](../../.github/branch-protection-policy.json) | تُراجع كجزء من أي تغيير حوكمي |

## العقد غير القابل للتخفيف

لا يجوز أن يحدث أي من الآتي في Pull Request مقبول:

1. إزالة `check_documentation_contract.py` من `guardrails` أو من `doc-integrity`.
2. إزالة `guardrails` أو `doc-integrity` من الفحوص المطلوبة للفرع `main`.
3. إضافة `continue-on-error` أو تحويل فشل التوثيق إلى warning.
4. توسيع `docs/archive/**` لإخفاء وثيقة تشغيلية أو إضافة استثناء بلا سبب حوكمي.
5. تعديل سياسة حماية الفرع دون مراجعة CODEOWNERS وتحديث سجل القرار.
6. دمج تغييرات توثيق دون تحديث المصدر الحي أو manifest عند الحاجة.

## نموذج التهديد

يحمي هذا النموذج من وكيل برمجي يعمل عبر Pull Request أو فرع عادي ويحاول تمرير وثيقة مكسورة أو تعديل تعليمات التشغيل أو حذف أثر التغيير. لا يحمي من مالك المستودع الذي يغيّر إعدادات GitHub خارج Pull Request، أو يملك صلاحية تعطيل الحماية، أو يبدّل هوية حساب CI. لذلك تبقى صلاحيات الإدارة، وحماية الإعدادات، والمراجعة البشرية المستقلة خارج حدود ما يمكن إثباته من ملفات المستودع وحدها.

## فحص الحالة الحية

يجب أن يثبت CI عبر GitHub API أن `main` ما زال يطابق السياسة المطلوبة. إذا غاب الفرع عن الحماية، أو غاب أحد الفحصين، أو انخفض عدد المراجعات، أو فُعّل force-push أو الحذف، يجب أن يفشل الفحص قبل قبول التغيير.

> **قاعدة القبول:** لا يكفي أن تكون الحماية مكتوبة في JSON أو Markdown؛ يجب أن تكون موجودة في إعدادات GitHub الحية، ويجب أن يكون CI قادرًا على كشف الاختلاف بين الحالة المرغوبة والحالة الفعلية.
