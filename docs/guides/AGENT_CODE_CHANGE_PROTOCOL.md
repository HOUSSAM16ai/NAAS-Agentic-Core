# بروتوكول تعديل الكود للوكلاء — Claude Code وCodex وأي وكيل آخر

## المبدأ

> **الوكلاء لا يملكون طريقاً مختصراً إلى الكود.** الأداة قد تكون Claude Code أو Codex أو غيرها، لكن سلطة التعديل مصدرها المستودع وقوانينه وبواباته فقط.

لا يطلب هذا البروتوكول من الوكيل أن يدّعي قراءة كل علم في العالم. يفرض بدلاً من ذلك سلسلة قابلة للإثبات: **اعتبار الكتالوج الكامل، تحميل المتطلبات المنطبقة، ربط كل مبدأ بتطبيق محلي، ثم إثبات الكود والإنتاج والقيمة**.

## دورة العمل الإلزامية

| المرحلة | ما يقرأه الوكيل | ما يثبت قبل الانتقال |
|---|---|---|
| 1. الهوية | `README.md`، `CLAUDE.md`، `AGENTS.md` | فهم هوية المشروع وحدوده وما ليس مشروعاً. |
| 2. السلطة | `AGENT_CONTEXT_REGISTRY.json`، الدساتير، ADRs، ملفات الحقيقة | معرفة القوانين التي لا يمكن تجاوزها وترتيب المصادر عند التعارض. |
| 3. المصادر | `SOURCE_ADOPTION_MATRIX.json`، جرد GitHub، بطاقات المستودعات | عدم وجود مصدر مخفي، وعدم استخدام `PENDING_CLASSIFICATION` كسلطة. |
| 4. الأكاديميا | `UNIVERSITY_CURRICULUM_CATALOG.json` و`CURRICULUM_APPLICATION_MATRIX.json` و`EVIDENCE_CATALOG.json` | اعتبار **كل مقرر في الكتالوج**، ثم اختيار المجالات المنطبقة وسبب عدم انطباق الباقي. |
| 5. المهمة | المواصفات، العقود، الحقيقة التشغيلية، قضايا المشروع | تعريف المشكلة، العميل/المستخدم، النطاق، المخرَج، والمالك. |
| 6. التصميم | ADR أو spec عند الحاجة | تحديد الحدود، الفشل، الأمن، الرصد، الاختبارات، الأداء، والتراجع. |
| 7. التنفيذ | أقل إضافة لازمة، دون حذف أو استبدال صامت | كل تغيير قابل للتتبع إلى معيار ومقرر/دليل ومسار محلي. |
| 8. البرهان | بوابات المشروع، اختبار سلبي، `git diff --check` | دليل أن الفارض يفشل عند خرقه، وليس مجرد نجاح مسار سعيد. |
| 9. القيمة | `OFFER_CATALOG.json` ودليل العميل | ربط القدرة بمشكلة مدفوعة ومسار عملة صعبة، أو تسجيل استثناء تأسيسي صريح. |
| 10. التوثيق | `DOCUMENTATION_CONTRACT.md`، `DOCUMENTATION_MANIFEST.json`، مصدر الحقيقة ذي الصلة | لا أمر قديم، ولا رابط مكسور، ولا تكرار لحقيقة تشغيلية؛ بوابة التوثيق تفشل عند الانحراف. |
| 11. التسليم | `CURRENT_CODE_ACCEPTANCE_PACKET.json` | حزمة مكتملة وبصمة diff حديثة ونتيجة `PASS`. |

## قاعدة المقررات الكاملة

الكتالوج الكامل يعني أن كل مقرر ظاهر في المصدر الرسمي موجود في سجل المشروع وله بطاقة مجال وتطبيق. لا يعني ذلك أن كل مقرر يصبح قاعدة عمياء لكل مهمة؛ ذلك سيحول المعرفة إلى ضوضاء ويشجع الادعاء الكاذب. القاعدة المنضبطة هي:

1. **كل المقررات تُعتبر ولا يُخفى أي مقرر.**
2. **المجموعة الأساسية لا تُسقط:** Harvard CS50x، مجالات متطلبات Harvard CS، NIST SSDF، وOWASP Agent Security.
3. **المهمة تحمل ما ينطبق:** تغيير الأنظمة يحمّل الأنظمة والأداء، تغيير نموذج يحمّل التعلم والبيانات والتقييم، تغيير وكيل يحمّل الهوية والأدوات والذاكرة والأمن، وتغيير تعليمي يحمّل التعلم وسوق الشغل والأثر.
4. **غير المنطبق يُفسَّر ولا يُهمل:** يسجل packet سبب عدم انطباق المجال، دون حذف المقرر أو الادعاء بتطبيقه.
5. **التطبيق يحتاج دليلاً:** ظهور اسم المقرر أو المستودع في القائمة ليس برهاناً على تنفيذ مبدئه.

## بروتوكول قبل الكتابة

قبل إضافة أي كود، على الوكيل إنشاء أو تحديث حزمة `CURRENT_CODE_ACCEPTANCE_PACKET.json`. يجب أن تتضمن الحزمة المسارات المتغيرة، المستودعات والمعايير، الأدلة الأكاديمية والرسميّة، مصفوفة التطبيق المحلي، إثبات الإنتاج، التتبع التجاري، سياسة عدم الحذف، ومراجعة الكتالوج الكامل. عند تغيير التوثيق، يجب أيضًا تحديد مصدر الحقيقة وتحديث `DOCUMENTATION_MANIFEST.json` أو توثيق سبب عدم إضافة الملف إليه.

بعد إنشاء الحزمة، تُحدَّث بصمة التغيير من خلال:

```bash
python3 scripts/research/refresh_acceptance_diff_snapshot.py
```

ثم تُشغّل البوابات:

```bash
python3 scripts/fitness/check_code_acceptance.py
python3 scripts/fitness/check_agent_context.py
python3 scripts/fitness/check_source_adoption_matrix.py
python3 scripts/fitness/check_reference_backbone.py
python3 scripts/fitness/check_memory_coherence.py
python3 scripts/fitness/check_governance_registry.py
python3 scripts/fitness/check_documentation_contract.py
```

أي فشل يعني **لا دمج**. لا يجوز للوكيل تعطيل البوابة، تقليل الكتالوج، تغيير حالة مصدر، حذف دليل، إعلان جاهزية إنتاجية أو إيراد بلا دليل حي، أو تحويل فشل عقد التوثيق إلى تحذير. تغيير البوابة نفسها يحتاج قرارًا حوكميًا ومراجعة مستقلة؛ لا يحق للوكيل أن يثبت صحة التغيير بإضعاف الفارض الذي يقيّمه.

## حدود الصدق

الكتالوج الحالي يثبت اكتمال لقطة المصدر التي تم استخراجها، وليس كل مقرر تاريخي أو كل جامعة في العالم. إضافة جامعة أو مقرر جديد تتم بالإضافة مع مصدر أولي وتاريخ تحقق ومالك. كما أن هذه البوابات تثبت الانضباط وقابلية التدقيق؛ ولا تثبت وحدها وجود عقد أو دفعة أو نجاح سوقي. الإيراد بالعملة الصعبة لا يُعلن إلا بوثيقة حالة تحمل دليلاً قابلاً للمراجعة.
