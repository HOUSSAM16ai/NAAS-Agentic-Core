# سياسة الاختبارات والتغطية

> **المصدر التنفيذي:** أوامر `Makefile` وملف [`.github/workflows/ci.yml`](../../.github/workflows/ci.yml). هذه الوثيقة تشرح السياسة ولا تستبدل الأوامر الفعلية.

## 1. مبدأ الاختبار

الاختبار مواصفة للسلوك: يثبت ما يراه المستخدم أو العقد، لا تفاصيل التنفيذ التي يمكن تغييرها دون تغيير السلوك. يجب أن تكون الاختبارات حتمية وقابلة لإعادة التشغيل، وأن تعزل الشبكة والزمن وقاعدة البيانات عند اختبار الوحدة.

## 2. طبقات الاختبار

| الطبقة | ما تثبته | الموضع المعتاد |
|---|---|---|
| Unit | قواعد المجال والدوال المعزولة | `tests/unit/` |
| Contract | توافق العقد مع المزود والمستهلك | `tests/contracts/` و`docs/contracts/` |
| API | سلوك HTTP/WebSocket ومسارات الأخطاء | `tests/` و`tests/integration/` |
| Integration | تفاعل المكونات عبر الحدود | `tests/integration/` و`tests/microservices/` |
| Architecture/fitness | بقاء القوانين البنيوية والحوكمية | `tests/architecture/` و`scripts/fitness/` |
| Live smoke | صحة مكونات البنية التي تُقلع فعليًا | وظائف CI المخصصة، لا مجرد فحص YAML |

كل endpoint جديد يحتاج على الأقل إلى مسار نجاح ومسار فشل، وكل حادثة مغلقة تحتاج اختبارًا أو عقد transcript يثبت أن الفشل عاد إلى اللون الأحمر قبل الإصلاح.

## 3. التغطية: الحقيقة الحالية والطموح

حد التغطية التنفيذي الحالي هو **73% على نطاق `app/`** في مسار `make test` و`test-monolith` في CI. هذا الحد هو ratchet صاعد: يمكن رفعه، ولا يجوز خفضه أو كتابة رقم أعلى في وثيقة توحي بأنه مطبق بالفعل.

الهدف طويل الأمد هو الاقتراب من تغطية كاملة للمسارات الحرجة، لكن عبارة «100%» هنا **هدف** وليست حالة حالية. لا يجوز استخدام الهدف كبديل عن نتيجة تقرير تغطية فعلي.

```bash
# المصدر المحلي المعياري؛ يشغّل pytest مع --cov=app و--cov-fail-under=73
make test
```

حدود النطاق مهمة: تقرير `--cov=app` لا يثبت تغطية `shared/` أو `microservices/` أو `frontend/`. لكل نطاق بوابته واختباراته الخاصة.

## 4. فحوصات ما قبل Pull Request

نفّذ الأوامر من جذر المستودع، وبالترتيب التالي:

```bash
git diff --check
make gates
make test
```

`make gates` هو المسار الكامل لفوارض CI المعمارية؛ `make guardrails` مجموعة فرعية وليست بديلًا. أما `make ci` فهو alias تاريخي لفحوصات محلية عامة، لذلك يجب عدم اعتباره نسخة مطابقة لكل وظائف CI. المرجع الملزم هو workflow نفسه.

## 5. الاختبارات المعزولة

استخدم `sqlite+aiosqlite:///:memory:` في اختبارات الوحدة عند توافق المكون، واعزل `get_db` عبر `app.dependency_overrides` في اختبارات المسارات. لا تتصل بقاعدة بيانات إنتاجية من اختبار وحدة، ولا تضع بيانات شخصية أو أسرارًا في fixtures أو سجلات CI.

## 6. التعامل مع الفشل والـ skips

الفشل الذي لا يمكن تفسيره لا يُحوّل إلى نجاح بتوسيع قائمة deselect أو بإضافة `|| true`. إذا كان هناك اختبار متذبذب، سجّل السبب المحتمل، عدد الإعادات، المسار المتأثر، والـ Issue المالك. يجب أن يكون أي استثناء مؤقت معلنًا وقابلًا للإزالة، لا قناة صامتة لتجاوز البوابة.

لا تعتبر عملية الإقلاع دليلًا على صحة خدمة. اختبارات live يجب أن تثبت health، والعقد، والمسار الأساسي، وسلوك الفشل، والتنظيف بعد الاختبار.

## 7. العلاقة مع التوثيق

عند تغيير أمر أو حد تغطية أو نطاق اختبار، حدّث `Makefile` أو CI أولًا، ثم هذه الوثيقة و[`START_HERE.md`](../START_HERE.md) و[`CONTRIBUTING.md`](../../CONTRIBUTING.md) في نفس التغيير. بوابة [`check_documentation_contract.py`](../../scripts/fitness/check_documentation_contract.py) تفشل إذا ظهرت تعليمات قديمة أو تعارضات معروفة.

> **قاعدة:** نتيجة اختبار موثقة بلا أمر قابل لإعادة التشغيل ليست دليلًا؛ ورقم بلا نطاق ومصدر ليس قياسًا.
