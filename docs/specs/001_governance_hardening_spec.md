## ② التصميم (design) — كيف بنيوياً

### الجذر ١ — الساق الثالثة على الفارض

`CLAUDE.md §6.6` يفرض على كل قدرة برهاناً ثلاثياً: `import + call chain + runtime
evidence`. و`check_spec_kit_governance` (D-265 L3) كان يفحص من ذلك **ساقين** على
الفوارض: الذِّكر (≈ import) والوجود (≈ call chain)، بلا **التنفيذ** (= runtime
evidence). فبوّابةٌ ميتة تجتاز «لا بوّابة يتيمة» وهي لا تفرض شيئاً.

الحلّ: سجلٌّ واحد قابل للقراءة آلياً + بوّابة فوقية تقيس **القرص مقابل التنفيذ**.
⛔ **لا يُكتب في السجلّ ما يمكن اشتقاقه** (D-192): التنفيذ يُمسَح ولا يُدوَّن.

### الجذر ٢ — الغياب ليس إذناً

الحارس المكسور، حرفياً، في **ستّة** مواضع:

```python
if _canonical is not None and _canonical.canonical_id != "probability":
    return None            # ← لا ينفَّذ أبداً لسؤال فيزياء: _canonical is None
```

سؤال «قانون أوم» يُرجِع `None` من `CANONICAL_TOPICS` (لا يعرف الفيزياء)، فالشرط يسقط
عند ساقه الأولى **فلا يعمل الحارس**، ويمضي السؤال إلى العقل الاحتمالي.

القاعدة المُصحَّحة — امتدادٌ مباشر لـD-191 («السقوط إلى المرجعي يتطلّب إشارةً موجبة»):

> **غيابُ الموضوع من سجلّ الاسترجاع ليس إذناً بالاحتمالات. إشارةُ مادةٍ موجبة من
> المنهاج (فيزياء · علوم) تجعل السؤال أجنبياً عن الاحتمالات بالبناء.**
