## الدورة المعتمدة (D-265 §2)

```
① NN_plan.md    — ماذا ولماذا
② NN_design.md  — كيف بنيوياً (+ ADR إن لزم)
③ NN_tasks.md   — وحدات تنفيذ مرقّمة
④ NN_spec.md    — العقد النهائي: مدخلات · مخرجات · حدود · عتبات
⑤ تنفيذ         — كود + اختبارات تحرس العقد
⑥ برهان نهائي   — E2E حيّ + بوّابة خضراء + توثيق محدَّث (يُسجَّل في `spec.md §17b`)
```

## عتبة «الجوهري» (D-265 §2)

الدورة الكاملة **ليست** لكل تغيير. تلزم عند مسّ: بنية (schema · حدود التنسيق) · سلوك
ذكاء اصطناعي (محرّك · مهارة · موجّه تربوي) · بيانات (هجرة · نموذج جديد) · واجهة عامّة
(API). وإصلاحٌ نصّي أو تعليقي لا يستوجب إلّا تحديث التوثيق المعني.

## القواعد

1. **المواصفة تُحدَّث في الدفعة نفسها** التي تحمل الكود (L1) — لا «لاحقاً».
2. **عقدٌ مقيس لا نثرٌ إنشائي** (L2): جدول مدخلات/مخرجات/حدود، أو نمط عقدٍ مُعلَن.
3. **كل قانونٍ يسمّي فارضه** — والفارض يجب أن يوجد **ويُنفَّذ** (D-265 L3 + D-266 L1).
4. `docs/adr/` تبقى موطن قرارات المعمار، و`docs/contracts/` موطن عقود الـAPI. هذا
   المجلد لا ينافسهما — يربطهما بدورة التنفيذ.
