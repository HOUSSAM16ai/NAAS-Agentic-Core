# عقود الترانسكريبت — الكارثة تصير اختباراً دائماً (D-186)

## القاعدة الدائمة

> **لا يُغلَق بلاغ كارثة بلا ملفّ عقد هنا.**

كل كارثة يبلّغ عنها المالك (ترانسكريبت حيّ يُظهر رداً خاطئاً على الطالب) تُترجَم إلى
ملفّ YAML في هذا المجلد. المُشغِّل `tests/test_transcript_contracts.py` يُعيد تمثيل
الأدوار على **مراحل الدور الحتمية نفسها** التي يمرّ بها الطالب حيّاً — لا على إعادة
تنفيذٍ موازية (اختبارٌ يعيد بناء المنطق يختبر نفسه لا النظام).

**لماذا:** ثلاث كوارث متتالية (ISS-128 · ISS-138 · ISS-139) كان جذرها واحداً، وكلّها
أُغلقت باختبارات وحدة تفحص دالّة بعينها. فحين تحرّك الجذر إلى طبقة أخرى، لم يلتقطه شيء.
العقد هنا يفحص **ما يراه الطالب**، فيبقى صالحاً مهما أُعيد تنظيم الطبقات تحته.

## الصيغة

```yaml
id: iss139_yaqsud_c          # مُعرِّف البلاغ
title: وصف سطر واحد
issue: ISS-139               # للتوثيق
turns:
  - student: "ماذا يقصد بالحرف C"
    must_contain: ["التوافيق"]          # نصّ يجب أن يظهر
    must_not_contain: ["165"]           # نصّ يُمنع ظهوره
    must_not_start_with: "## مثال ملموس"  # الجواب لا يبدأ بهذا
    must_answer: true                    # الدور يجب أن يُنتج جواباً حتمياً
```

الحقول كلّها اختيارية عدا `student`. غياب حقلٍ يعني «لا قيد» — لا تفترض شيئاً ضمناً.

## التشغيل

```bash
pytest tests/test_transcript_contracts.py -v
```

## التجربة السلبية إلزامية

عند إضافة عقد لكارثة جديدة: **شغّله قبل الإصلاح وتأكّد أنه أحمر**. عقدٌ يمرّ على الكود
المعطوب لا يحرس شيئاً.
